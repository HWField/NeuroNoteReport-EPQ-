Whilst exploring and testing thee pages on a variety of devices however I noticed that the load times were quite poor. To quantify this I visited Google's page speed insights service which gave my site scores in a number of categories, due to research and implementation of accessibility tools I scored well(achieving 81) in the accessibility category and only losing marks due to now unused images not having text descriptions however my performance score was 36 which is quite poor. Whilst a lower score can be expected for webapps such as this when compared to much simpler 'static' websites this poor score was due to an overly large number of code 'packages' being served from a slow server. 

\begin{figure}[H]
    \centering

    \caption{Google's performance report}

After doing some testing on where the slowdowns originated it turns out that some of the software libraries I use for functionality (such as the mathematical Katex library) were sending much more code/features than were actually required and that these large files weren't being cached by my Cloudflare CDN (content delivery network that takes note of commonly requested data such as the welcome page and caches it in all of Cloudflare's worldwide datacentres rather then having to have my Raspberry pi at home relay the information and thus saving time) and had to take the slower route from my house. My testing of load times hadn't caught this as once my computer had initially loaded that data it was kept for future browsing session and that initial load also didn't take very long due to my close proximity to the server (which was just next to me).

To solve these performance issues I took two approaches: firstly I went through each and every library I am using and made sure they were 'tree shakeable', this means that when I 'build' my code into he final distributable software that my server sends to user it can intelligently remove any library code that isn't used, massively reducing the code required by each client. In fact having completed this process I brought my 'package size' from 5000kB down to just 700kB - a huge improvement. Secondly I switched from hosting the frontend code on my server to entirely running on Cloudflare's CDN, whilst all of the functional backend (and backup frontend) run on the pi any user now has access to a lightening fast copy of my webapp. Finally I removed all of the unused images and assets previously identified

With these performance updates complete I retested my project and saw my scores jump up to an incredible 97 in performance and 96 in accessibility

Lastly this week I found myself unable to tell if my project was operating smoothly or if my users would be facing errors so I researched a variety of technique to get instant reports if something goes wrong. I settled on using a platform called uptime robot (whilst I could build something myself, should I lose internet / have a power cut at home it would render the system pointless). I built a API health check page on my server which Uptime Robot would attempt to connect to every 5 minutes, if the connection failed for whatever reason. I am sent an email notification and a SMS (text) message with the details so that I can resolve them. Tools such as this are crucial in 'professional' software environments and by integrating them into my project now I am setting myself up for future success
